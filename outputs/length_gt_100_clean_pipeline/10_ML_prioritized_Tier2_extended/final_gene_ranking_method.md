## What The Ranking Score Uses

`ML_priority_score` is a composite score clipped to the 0-1 range. It was generated by the stable ML-prioritized Tier 2 procedure using these weighted terms:

- 0.40 x `selection_frequency_combined`
- 0.15 x region-scaled `model_support_count`
- 0.10 x `sparse_model_support`
- 0.15 x `importance_rank_score`
- 0.10 x `sign_consistency_score`
- 0.05 x region-scaled statistical diagnosis evidence
- 0.05 x strict-v2 support score

The statistical diagnosis evidence score was based on `abs(standardized_effect_size_diagnosis) * -log10(p_value_diagnosis)`, scaled within region/subregion before entering the composite.

## How Tier 2 Evidence Contributes

All rows in the final ranked table are Tier 2 candidate gene-region pairs. Tier 2 provided the statistical candidate pool using nominal diagnosis evidence and standardized effect-size filtering. In this final documentation table, broad-region rows are labeled with `source_model = grouped_region_LMM`, while frontal subregion rows are labeled with `source_model = frontal_subregion_fixed_effect_sensitivity`.

## How ML Support Contributes

ML support comes from repeated `Tier2_fixed` v1 feature-importance evidence and the strict-v2 stability branch. Strict-v2 selection and top-k construction occur inside the training data. The majority-class baseline does not use genes and, after the correctness fix, is excluded from v2 gene-event counts and the v2 event denominator.

The v1 denominator is 125 events per region (five feature-using model families × five repeats × five folds). The corrected v2 denominator is the dynamically counted non-baseline grid: 150 events per region in this run (two train-only selectors × five top-k values × five feature-using models × three outer folds). The old frozen v2 denominator was 180 because it included the majority-class baseline.

## Tier4_top-k Status

Tier4_top-k feature sets were generated historically as support/sensitivity layers, but the current final extraction code filters v1 input to `Tier2_fixed`. Tier4 v1 rows therefore do not contribute to the currently exported final priority score.

## Model Support And Direction Consistency

Sparse model support captures support from L1/Elastic Net-style sparse linear models. Linear model support captures linear model coefficient evidence. Random Forest support captures exploratory, non-directional tree feature-importance evidence and may contribute to selection, model support, and rank, but not sign consistency or ML direction. Sign consistency uses only L1 logistic, L2 logistic, elastic-net logistic, and linear-SVM coefficients. Missing directional evidence is scored neutrally as 0.5 in the weighted score but cannot satisfy the high-confidence sign-consistency gate.

Predictive-performance metrics such as ROC-AUC do not enter the gene-priority score.

## Confidence Class Assignment

High-confidence ML-prioritized Tier 2 genes required:

- `ML_priority_score >= 0.70`
- `selection_frequency_combined >= 0.50`
- `model_support_count >= 2`
- sparse model support
- `sign_consistency >= 0.70`
- no false statistical/ML sign agreement

Moderate-confidence ML-prioritized Tier 2 genes required:

- `ML_priority_score >= 0.45`
- `selection_frequency_combined >= 0.25`
- `model_support_count >= 1`
- no false statistical/ML sign agreement

All other ranked Tier 2 rows are retained as exploratory/low-priority candidates.
